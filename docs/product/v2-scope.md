# StorePilot V2 - Product Scope

## 1. Purpose

StorePilot is a local retail management system designed initially for a single shop.

The second release focuses on the essential daily shop operations while maintaining data integrity, maintainability, testability, and a clear architecture.

The goal is to deliver a reliable working system, not to implement every possible retail or accounting feature.

## 2. Deployment Scope

- Single shop.
- Single local SQLite database.
- ASP.NET Core Web API running locally.
- React + TypeScript frontend.
- Desktop integration is planned through a WebView-based shell.
- No cloud synchronization in V2.
- No multi-branch or multi-warehouse support in V2.

## 3. V1 Features

### Core Data
- Units.
- Product groups.
- Products.
- Customers.
- Payment methods, if more than one method is required.

### Sales
- Create and post sales invoices.
- Support cash sales without a registered customer.
- Require a registered customer for credit sales.
- Support full and partial payments.
- Support multiple payments on an invoice only if required by the shop's payment workflow.

### Customer Accounts
- Customer account ledger.
- Customer account statement.
- Partial and full debt collection.
- Customer opening balances if existing debts must be migrated.

### Returns
- Create sales returns linked to original sales invoice items.
- Validate previously returned quantities.
- Update stock.
- Refund the customer or offset the return against an existing customer debt.
- Do not automatically retain customer credit balances in V2.

### Inventory
- Record stock movements generated by sales and returns.
- Maintain current product quantities.
- Display basic stock information and movement history.

### Cash
- Record actual cash inflows and outflows generated by supported operations.
- No advanced cashbox or financial-account management in V2.

### Quotations
- Include only if confirmed as a required V2 feature.
- No stock, cash, or customer-ledger impact before conversion.

## 4. Deferred Features

The following features are outside the initial implementation scope:

- Suppliers and supplier accounts.
- Purchase invoices and purchase returns.
- Supplier payments.
- Multiple warehouses.
- Multiple branches.
- User accounts and permissions.
- Advanced financial accounts.
- Automatic FIFO payment allocation.
- Per-invoice payment allocation and outstanding balances.
- Full accounting system.
- Cloud synchronization.
- Advanced reporting and analytics.

These features must not be implemented prematurely.

## 5. Explicit Business Boundaries

- Anonymous sales must be fully paid.
- Credit sales require a registered customer.
- Customer receipts cannot exceed the outstanding balance unless an approved refund/credit workflow is introduced.
- Returns must reference original sale items in V1.
- Returns cannot exceed the remaining returnable quantity.
- Posted financial documents cannot be silently edited or deleted.
- Related financial and stock operations must be committed atomically.

## 6. Development Principles

- Keep responsibilities separated.
- Enforce important constraints in the database and application layer.
- Use EF Core migrations as the database schema history.
- Test critical business workflows.
- Avoid unnecessary abstractions and premature features.
